Chalk Runner · distributed state

Every room had its own global leaderboard

The board of the day looked right in every room, and was wrong everywhere.

Waseem Ahmad Ansari

Chalk Runner has a board of the day: the furthest anyone has run since midnight, drawn on the blackboard as a red line you are trying to get past. It is the whole reason to play a second round. Without it a run is a number you forget.

The game lives on Cloudflare Workers with Durable Objects. A Durable Object is a small piece of server with storage attached, and the platform guarantees there is exactly one instance for a given name, wherever in the world requests come from. Chalk Runner names one per room, so a room is a Durable Object: it owns the players, the level, the physics loop, and its own storage.

When a round ended, the room did this:

// in the room
await this.recordScore(name, metres);

Which reads perfectly and is completely wrong.

What was actually happening

this is the room. this.recordScore wrote the record into the room's own storage. Every room had a leaderboard, and every one of those leaderboards contained only the runs that had happened in that room.

Inside a single room this is invisible. You run 340 metres, the board says 340. Your friend runs 380, the board says 380. Play a third round, the line moves. Everything you can see is consistent, which is why it survived weeks of me testing it, because I was always testing one room.

What was missing was everybody else. The record was supposed to be the furthest run anyone had made that day. What each player was actually looking at was their own room's high score with the word "record" on it. The feature that exists to connect players who will never meet had quietly become a feature about yourself.

Why tests did not find it

Every test I had written created a room, put two clients in it, played a round, and asserted on the result. With one room, "the board" and "this room's board" are the same object and no assertion can tell them apart.

The test that finds this is two rooms. Play a round in room A, play a shorter round in room B, and assert that room B is told about A's record. I did not have that test because I had never written a bug that needed it — which is a circular reason, and the reason most gaps in a suite exist.

The fix

One Durable Object with a fixed name, __board_v1__, that owns the board. Rooms no longer keep scores, they forward them:

// in the room: hand the score to the one object that owns the board
async postScore(name, metres) {
  const id = this.env.ROOM.idFromName(TOP_ROOM);
  await this.env.ROOM.get(id).fetch('https://do/score', {
    method: 'POST',
    body: JSON.stringify({ name, metres })
  });
}

Two details are worth pulling out.

The name is versioned. __board_v1__ rather than board, because a Durable Object's storage is tied to its name and the day I need a different shape of record I want a clean object rather than a migration on a live one.

The internet can read the board but cannot write to it. /api/top is GET only from outside; the write path is reachable only from another Durable Object in the same Worker. A leaderboard with a public write endpoint stops being a leaderboard within about a day of anyone noticing it.

The default that lied

There was a small coda. With a real shared board, the very first run of a brand new day compared its distance against an empty record, which was initialised to zero, and the end screen announced that the player was level with the record. Technically true. Read as sarcasm by the only person who will ever see it.

The fix was to stop using zero to mean two different things. A separate recordSeen flag distinguishes "the record is zero" from "there is no record yet", and an empty board now says First name on the board, which is a nicer thing to be told anyway.

What I take from it

"Global" is a claim about where state lives, and nothing enforces it. In a system where every instance can hold storage, writing to the wrong instance compiles, deploys, and reads back exactly what you wrote. The bug is not in the write. It is in which object you were holding.

Test the plural. One room, one user, one tenant, one region: in every one of those the local and the global collapse into each other. If a value is meant to be shared, the test has to contain two of the things it is shared between, or it is not testing sharing at all.

Watch for defaults doing double duty. Zero meaning "no record" and zero meaning "a record of zero" were fine until the two of them were in the same sentence in front of a player.
